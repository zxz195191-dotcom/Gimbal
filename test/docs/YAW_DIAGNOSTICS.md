# Yaw 编码器小角度诊断（仅观测版）

本版不修改 PID、补偿表、前馈斜坡、制动/收尾、积分或 boost 开关。
常规 VOFA 九列及原发送周期不变。采样路径无 printf、串口发送、等待或动态内存分配。

## 先保存新 Pitch 表

用户本次重新 pcal 的表尚未写回源码。烧录/复位会恢复源码旧表，先保存完整导出数据。
不要以本次旧表固件的 Pitch 表现判断新表效果。此诊断不自动运动 Pitch 或自动使能 Yaw。

## 每组测试

串口为原 USART2，115200、8N1，命令加换行。保持既有参数；积分和 boost 应为关闭。

1. `ye` 后等待轴 ACTIVE，再 `ymode 0`。选定起点；同组录制期间不再切模式。
2. `ydiag arm`：仅准备采样，不改变控制；等待下一条成功接收的 `y/yr` 才开始。
3. 发 `yr 0.5 1`。保留普通 VOFA 波形，等待至少 5.2 秒，让缓冲自动冻结。
4. 发 `yd` 撤掉 Yaw 力矩。采样不会丢失，Pitch 状态不变。
5. 切串口文本记录并保存原始接收数据，发 `ydiag dump`；等收到 `#YD_END`。
6. 同样步骤对 `yr 0.5 5`、`yr 0.5 20` 分别录制，尽量保持同一起点、方向和机械条件。

开始另一组前应完成上一组导出；新的 `ydiag arm` 会覆盖上一次捕获。
`ydiag stop` 可提前冻结记录，不改变电机目标或使能状态；随后仍需 `yd` 再导出。
命令确认沿用原串口的 LED 回应，错误不额外混入普通数值波形。

arm 要求 Yaw ACTIVE、编码器模式，且未在 ycal/ytest、积分和 boost 关闭；不满足则拒绝，
不会替用户改变开关。dump 要求 Yaw DISABLED 或 FAULT，以免把导出格式化放到运动测试期间。
故障、停用、模式切换会冻结当前记录；CAN 发送失败帧保留结果，不能当作已送达帧。

## 记录与导出

- 1024 个定长样本，正常 5 ms 控制周期覆盖约 5.12 s；周期不规则时覆盖长度随之变化。
- 缓冲占 135168 字节普通 SRAM。本次 ARM 链接 RAM 总用量约 144944 字节/192 KiB。
- 每帧在最终 MIT 调用前读取同一 CAN 反馈快照和控制状态；实际打包的 CAN 字节在发送前
  解码，随后附上 HAL 发送结果。HAL_OK 只代表 CAN 邮箱受理，不代表驱动已收到或执行。
- 记录最终目标、编码器位置/速度、限幅前后命令、最终 p_des/v_des/kp/kd/t_ff、
  drive/arrived/制动距离、摩擦目标/收尾前状态/实际状态、反馈力矩、帧年龄和控制周期。
- 同时保留量化后的五个 MIT 参数及基于它们的 P、D、总力矩估计，便于区分浮点命令与线上命令。
- 角度前缀 `target/encoder/command` 是逻辑关节坐标；`raw_position`、MIT 参数和估算/反馈力矩
  是电机坐标。CSV 字段明确标注 deg、rad、deg_s、rad_s 和 nm。
- `drive=nan, arrived=255` 表示本帧没有运行普通动态分支，不伪装为 arrived=0。
- `g_yaw_diag` 为调试器状态；state：0空闲、1待触发、2记录、3冻结、4导出。
- stop：1缓冲满、2手动冻结、3轴停用、4故障、5模式/标定切换。
- `max_record_cycles` 是 Prepare、MIT 解码和样本提交三段诊断函数的周期累计最大值，
  不含控制计算、CAN 调用及采样字段准备；仅 ARM 实机 DWT 有意义，主机测试为0。
  上板仍需检查它和 `dt_ms`，本轮尚未测得实机开销或最坏控制周期。

导出走现有 UART DMA 报告通道，每个样本分成 A/B/C 三行；每行只在 DMA 受理后推进。
导出期间暂停普通数值帧，完成后自动恢复；不会将诊断字段追加到原九列。完整导出约需一分钟。
先采样、后导出，因此原串口带宽不会限制 200 Hz 的内存采样。

转换原始串口日志：

```powershell
python tests/pitch_continuous/decode_yaw_diag.py yaw_1.log -o yaw_1.csv
```

脚本将 A/B/C 合并为单行 CSV，拒绝缺帧、重复帧、列数不符或缺少结束标记的数据，
并输出末500ms误差、速度、估算力矩及限幅次数摘要。它不把摘要自动判断成实机根因。

## flags 位掩码

| 值 | 含义 |
| --- | --- |
| 1 | 本帧运行普通 Yaw 动态参考 |
| 2 | 动态参考相对实际位置的±2°限幅 |
| 4 | 命令推进受设定速度限制 |
| 8 | 推进后的命令相对实际位置的±2°限幅 |
| 16 | MIT 原始位置±12.4rad边界限幅 |
| 32 | 末级估算力矩/位置区间投影修改了命令 |
| 64 | 收尾/换向逻辑主动降低或清空已有摩擦状态 |
| 128 | 控制间隔无效（0或超过20ms） |
| 256 | 传给打包函数的字段超出协议范围；量化误差本身不置此位 |
| 512 | 自上一采样帧以来发生负载补偿 Reset |

`friction_before` 是本帧收尾裁剪前的状态；`friction_goal` 是规划速度计算的目标；
`friction_actual` 是收尾裁剪及斜坡更新后的状态。对照位64可以直接检查撤补偿发生的时刻。

估算公式：`P=wire_kp*(wire_p-raw_position)`、
`D=wire_kd*(wire_v-raw_motor_rate)`、`total=P+D+wire_ff`。
这些不是实测电流/轴力矩；驱动量程、限流及负载仍需实机核对。
