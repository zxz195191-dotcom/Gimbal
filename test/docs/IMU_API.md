# IMU 模块接口与简洁记录

本次只完善 IMU 对外接口，不修改电机控制、Pitch 标定、温控参数、Fusion 参数，
也不修改已有“采样异常后姿态锁定”的故障策略。偶发故障仍是待处理事项。

## 给上层代码的唯一姿态读取入口

主循环顺序保持：`IMU_Service → IMU_HeaterService → IMU_AttitudeService`，
随后使用 `IMU_AttitudeGet(HAL_GetTick(), &attitude)` 获取一份一致的最新快照。

```c
#include "imu_attitude.h"

IMU_AttitudeSample_t attitude;
if (IMU_AttitudeGet(HAL_GetTick(), &attitude)) {
    /* 数据有效并且采样年龄 <= 5 ms。
     * pitch_up_rad: 抬头正，rad。
     * gyro_body_rad_s[1]: 原右手系Y角速度，抬头负，rad/s。
     * 这是机体角速度，不是直接计算好的云台关节速度。
     * 此处仅示意读取，尚未接入任何电机控制。 */
} else {
    /* 不得把 out 中保留的历史角度作为有效闭环反馈。
     * 由上层自己的失效策略处理，不能只在这里“什么也不做”。 */
}
```

此接口仅限与 IMU_Service 相同的主循环上下文调用，尚不是 RTOS/ISR 跨上下文接口。
不重置芯片、不做校准、不消耗或推进数据，也不重复积分；只读取已处理的数据。
控制周期比采样周期慢时，通过 sequence 区分新帧；不应假设每次读取都是新样本。

| 字段 | 含义 |
|---|---|
| quaternion_wxyz | 右手系传感器/机体到 NWU 世界的四元数，顺序w,x,y,z |
| roll_rad / pitch_up_rad / yaw_left_rad | rad；pitch_up是原ZYX pitch的负值，yaw_left范围约±π |
| yaw_continuous_rad | double，解开±π回绕的航向；不会消除六轴漂移 |
| gyro_body_rad_s | 去零偏后的机体XYZ角速度，rad/s，内部不翻单轴 |
| accel_body_mps2 | 本次融合输入的原始机体加速度计比力，m/s²；不是去重力的线加速度 |
| timestamp_ms / timestamp_cycles | **最后一次融合输出对应的DRDY采样时刻**，HAL毫秒/DWT计数 |
| sequence / dt_s | 原始采样序号、本次融合所用间隔s |
| age_ms | 当前读取时刻减采样时刻；从未产生姿态时为UINT32_MAX |
| reference_id | 同一次MCU运行内，每次重启/开始重新校准时改变；不跨断电保存 |
| valid | READY、数据年龄不超过5ms且无现有姿态故障；不代表实车性能已验收 |
| heading_continuous_valid | valid且连续航向可解释；消费连续航向必须另检查此项 |
| accel_rejected / thermal_ready | 本帧重力修正被拒绝 / 当前温控已稳定 |
| state / error | 当前状态、错误，编号保持原样 |

冻结后新原始采样可能仍来，但不会刷新旧姿态的 timestamp/sequence，使历史输出冒充新数据。
重新校准后 reference_id 改变，上层应废弃依赖旧IMU参考系的目标/相对零点；不要把旧目标
直接套到新航向零点。本接口不替上层决定重新使能电机。

机体Z角速度不普遍等于世界Yaw角速度。A板跟随Pitch转动，接云台速度反馈时必须结合
安装方向与当前姿态做轴投影，不能直接把某个欧拉角差分/某根gyro轴接进两个电机环。
目前安装映射仍沿用已验证的原生轴，不宣称完成全姿态下的关节速度转换。

连续航向依赖连续有效采样；当姿态经过 |ZYX pitch| >=85° 的近垂直区，或算法量程恢复时，
圈数可能无法唯一解释，heading_continuous_valid 会锁为0，直到重新校准。
此时四元数/机体角速度仍由valid单独标识，不把Euler奇异性当成全部传感器失效。
±180°普通航向跨界本身不触发这个限制。

## 看波形/把记录交给别人

原 `imu 1/2/3/4` 字段数量、单位和顺序全部不变。
新增可选 `imu 5`，六列固定为：

`sample_time_ms, roll_deg, pitch_up_deg, yaw_continuous_deg, temperature_c, valid`

- 第1列来自板上采样时刻，不用串口接收时间估计采样延迟。
- 第2～4列是姿态，VOFA只打开这三条曲线即可；温度与valid按需看。
- 第6列要求姿态和连续航向都有效。为0时不要用平直曲线判断“零漂很小”。
- 从未产生融合输出时各数值为0且valid=0；故障后保留历史采样时刻、历史温度和角度。
  当前温度/故障原因用原 `imu 4` 查看。
- 输出频率仍约10Hz，内部融合约1kHz。该日志用于看趋势/漂移/角度回绕，不能据此测1ms级响应。
- 数据时间戳自MCU启动开始，不是墙上时钟；49.7天左右无符号回绕，跨重启须分文件记录。

使用串口工具的“保存接收数据”功能，保存为 `.txt` 后直接作为附件提供，不必手动复制。
建议一次文件只使用一种 `imu` 模式，并附一句动作说明，如“静止30秒，左转两圈，再反向一圈”。
不要把模态切换导致的列含义变化当成数据异常；重新校准/重启后建议开新文件。
这里不添加板内长时间缓存、Flash日志或上位机新程序。
