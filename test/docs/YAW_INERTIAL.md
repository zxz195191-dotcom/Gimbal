# Yaw 相对航向控制

Pitch控制、0～41°扫描、补偿表和增益保持现有版本。IMU采集、零偏、恒温和Fusion姿态解算不改。

## 直接使用

串口仍为USART2，115200、8N1，命令带换行。

1. 使用原有IMU校准流程，`imu 4`查看姿态状态；需要常温重新校准时保持机构静止并发`imucal`，等待state=3。已经READY则不用重做。
2. `ye`使能Yaw，`ymode 0`选原电机模式并返回电机波形。先发`yr 5 5`，观察编码器与IMU航向增减是否一致。
3. `ymode 1`切惯性模式：当前航向定义为0°，目标与内部命令同时为0°，编码器原零点不变。随后`y 5 5`表示相对本次切入航向的+5°，命令推进速度5°/s；`yr -5 5`表示相对当前惯性实测的−5°。
4. `ytest -5 5 5`围绕本次切入零点持续往返；`ytest`围绕当前控制实测±10°。`ycancel`取消往返并保持当前命令，`yd`撤力停用。
5. `ymode 0`返回原电机模式，以当前编码器位置接住，目标不跳回上电零点。模式切换取消Yaw往返，不启动新的测试。

`ymode`只有0/1。切换需要Yaw处于ACTIVE；切惯性需要现有IMU接口返回有效姿态。不排队等待。失败看`g_yaw_inertial.switch_result`：1轴未使能、2姿态不可用、3模式参数错误；0成功。Yaw串口第6列才是实际模式，不以“发过命令”当作切换成功。

失联、IMU姿态失效或重新校准改变参考系时，惯性控制进入现有电机停用故障流程，`g_yaw_test.fault=YAW_FAULT_IMU`。`ye`重新使能回电机模式，不续跑测试；需要再次明确`ymode 1`。没有新增运动测试、稳速、停滞或样本筛选门槛。

## 正方向与安装

沿用工程已记录的传感器安装假定：X朝炮口、Y朝左、Z朝上；本次不能远程确认实物安装。

在`Core/Application/Module/Gimbal/yaw_inertial.h`改：

```c
#define YAW_IMU_DIRECTION 1.0f
```

`1.0f`使向左转时航向与航向角速度为正；`-1.0f`同时反转两者。应选与现有Yaw逻辑编码器正方向一致的值。只改宏并重新编译，没有反向串口命令。重烧录会丢失原有RAM Pitch补偿表，需要按原流程重新pcal。

同文件`YAW_FORWARD_SENSOR_X/Y/Z`是炮口前向在传感器坐标中的单位向量，当前(1,0,0)。不是把角速度直接当成某个固定轴；四元数提供传感器到世界的变换，三轴陀螺仪共同计算该前向的航向变化率。IMU随Pitch倾斜也按当前姿态计算，不用Pitch上电编码器角度冒充重力姿态。

电机方向仍由`gimbal.h`内`GIMBAL_YAW_DIRECTION`决定；它同时作用于编码器和电机输出。已有电机模式方向正确时，先只核对`YAW_IMU_DIRECTION`。

## 控制链与单位

`y/yr/ytest` → 当前模式目标 → 原速度限制产生内部命令 → 当前模式闭环 → 原CAN MIT帧。

- 电机模式：编码器位置/速度，驱动内置kp/kd，MCU力矩项为0。
- 惯性模式：MCU计算 `T = kp*(command-heading) + kd*(command_rate-heading_rate)`，MIT帧的kp/kd均为0，只发送T到力矩项。编码器继续更新机械位置，不再产生抵抗底座补偿运动的位置恢复力。

内部角度rad、角速度rad/s、力矩N·m；kp为N·m/rad，kd为N·m/(rad/s)。沿用现有Yaw kp/kd，不自动调参。`ykp/ykd`在惯性模式改变外部增益，电机模式改变内置PD参数。两者执行周期不同，不保证实机动态响应完全相同。

IMU给出body→world四元数R、去偏角速度w。前向f的世界投影u=R*f，导数du=R*(w×f)，航向速度为 `(u.x*du.y-u.y*du.x)/(u.x²+u.y²)`，角度取atan2(u.y,u.x)并连续展开。默认安装下等价于ZYX欧拉航向速度变换；不能拿原始gz代替。参考：[MathWorks 6DOF运动学](https://www.mathworks.com/help/aeroblks/6dofeulerangles.html)。炮口完全竖直时水平航向无定义，不输出除零结果。

当前力矩编码沿用驱动协议±10N·m，宏`YAW_MIT_TORQUE_MAX_NM`与`dm_motor.c`一致；这不是持续额定力矩，也不是已读取过驱动内部电流限制。六轴IMU提供相对航向，没有绝对北向，长时间会漂移。

## Yaw专用VOFA输出（imu 0，约20ms，纯数值）

`ye`选择Yaw，再用`imu 0`切回电机调试输出；成功执行`ymode`或`ytest`也会选择Yaw并进入此输出。只改变显示时用`ye`和`imu 0`，不必为了看数据重新切换控制模式。保持原串口、DMA和发送周期，没有新增框架。

固定9列，没有表头或文字混入数值帧。VOFA通道名称按以下名称设置：

| 列 | 名称 | 含义与单位 |
|---|---|---|
| 1 | target_deg | 当前Yaw模式的目标角度，°；不是内部渐进命令 |
| 2 | imu_yaw_deg | IMU相对航向，°；成功切换模式时归零 |
| 3 | yaw_rate_deg_s | 控制使用的角速度，°/s：模式0为编码器速度，模式1为转换后的IMU航向速度 |
| 4 | encoder_relative_deg | 编码器相对上次模式切换位置的角度，° |
| 5 | control_torque_nm | 发送的MIT力矩项，N·m，电机正方向；惯性模式为外部PD输出，电机模式为0（不代表驱动内部PD力矩为0） |
| 6 | yaw_mode | 0电机模式，1惯性模式 |
| 7 | imu_valid | 0无效，1有效；无效时航向保留旧值 |
| 8 | imu_age_ms | 有效IMU样本的年龄，ms；IMU无效统一为−1，不输出UINT32_MAX |
| 9 | yaw_state | 0停用、1清错、2等反馈、3核验、4正常控制、5故障 |

前5列画曲线，后4列看数值即可。内部控制变量的`_rad`和`_rad_s`表示真实弧度单位，保持不变；只在串口输出前换算为deg、deg/s。VOFA中旧的通道别名需要按此表手动重命名，纯数值串口不传名称。

Yaw帧不含MCU时间、测试阶段、电机反馈年龄、Pitch标定、轴选择或反向宏。发送间隔仍约20ms，DMA忙会跳过，因此VOFA横轴不能充当精确MCU时间。

Pitch通过`pe`、`ptest`、`pscan`或`pcal`选择，保留原15列独立输出：目标°、内部命令°、编码器角度°、速度°/s、反馈力矩N·m、前馈N·m、MCU时间ms、阶段、电机反馈有效、反馈年龄ms、校准状态、采样状态、采样时间ms、补偿查表有效、轴标识1。Pitch帧不附加Yaw数据。VOFA分别使用Yaw/Pitch配置，切轴时清掉旧曲线，避免列含义串用。

## 远程看哪几条曲线

固定底座，小幅正向运动：模式0比较第4列编码器增量与第2列IMU航向，应同向。惯性模式看第1～5列，目标增加时航向应增加，运动速度应为正，停稳后接近0。编码器与IMU可以有常量零点差，底座运动时也不应强求重合。

将Pitch分别保持低位与抬高后重复同一Yaw动作，第3列应继续正确表示航向速度；只动Pitch时，第2列与惯性模式的第3列应基本不变。这里只观察已有动作，不增加自动测试程序。

惯性模式保持目标时轻转底座：第2列应尽量保持，第4列反向变化。先确认第6列=1、第7列=1、第9列=4，再判断惯性闭环。运动中不用暂停MCU。

## 验证范围

沿用`tests/pitch_continuous/run.ps1`的直接C模拟：Pitch现有42节点/补偿回归；倾斜0～41°与带roll的角速度变换；纯Pitch/roll运动不产生虚假Yaw速度；跨±180°；非零姿态切换；内置PD为零；底座扰动、往返取消、IMU失效/重标定退出；反向宏单独编译验证。另运行原`tests/imu/run.ps1`。ARM构建与模拟通过不代表安装方向、实机稳定性、漂移和总线时序已上板验证。
